BROWSER AGENT · 踩过的坑

What did not work

泄漏

模板化 DONE 目标

「打开 X 页，打开即停」→ 模型学会「一看到 stop when 就 DONE」。DONE 必须用真实落地页。

泄漏

历史长度偏差

DONE 样本都带 1 步历史、CLICK 都不带 → 学到「有历史 ⇒ DONE」。必须加任务中途的负样本。

负优化

「不确定就升级给 8B/27B」

置信度门控升级反而更差：27B + 300 token 思考 = 4.7s/步、0.861/0.603；322M = 21ms、0.890/0.623。

无效功

其他

截断页面文字省不了事（头占满序列）；torch.compile 遇变长 batch 逐 shape 重编译，慢 6×。

带走的一句话

在这个任务尺度上，微调好的 322M 就是更好的决策者 —— 更大、更慢、更贵的老师并不自动等于更好的系统。

SNAKE · 实验设计

贪吃蛇：同一条食物序列，所有策略同屏 PK

公平对照

12×12 棋盘，所有选手跑完全相同的食物序列，直到死亡。规则智能体、搜索算法、零样本、微调、RL 全部同台，排行榜实时刷新。

SYNTHESIS

两条线，同一套方法论

①

状态表示决定上限

浏览器线：元素表挪进 option list → 6/16 → 10/16。贪吃蛇线：坐标清单换网格字符串 → 17.0 → 28.1。改「看到什么」比改「怎么训」便宜得多。

②

泄漏是隐形的

模板目标 →「stop when ⇒ DONE」；历史长度 →「有历史 ⇒ DONE」。两边共同的解法：用执行事实造标签，再加专门的中途负样本。

③

小模型 + 快循环赢

322M 单卡 1h 训完、21ms 决策；贪吃蛇一轮 RL 一分钟。「能不能一天迭代 10 个版本」比「模型多强」更决定项目成败。

如果只记一件事：先设计「模型每一步到底看到什么」，再造干净的数据循环 —— 模型大小可以最后再谈。

TAKEAWAYS

结论与下一步

已验证

322M 小模型是可以「住进引擎」的决策者

真实网页任务 62% 完成率、21ms/步、单卡复现（权重与全套脚本已开源可复跑）。它不需要 27B 老师兜底 —— 在它的任务尺度上它自己就是更好的决策者。

下一步

三个方向

1. 补强失败模式：长建议列表、滚动后分页、多步表单流；2. 更强的 DAgger 老师（当前 8B 已不足以带来增益）；3. 把蛇线验证过的「表示 A/B 测试」流程搬回浏览器线。
